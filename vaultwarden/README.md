# Vaultwarden deploy (Oracle box)

Deploys a self-hosted [Vaultwarden](https://github.com/dani-garcia/vaultwarden)
to the same Oracle instance as the kanban stack, reusing the existing SSH
secrets. Isolated from kanban: separate directory (`~/vaultwarden`), its own
containers, and ports **80/443** only (kanban keeps 3484/3485).

- **URL:** `https://vault.<ORACLE_HOST-with-dashes>.nip.io` (derived automatically;
  for host `129.159.69.183` → `https://vault.129-159-69-183.nip.io`)
- **TLS:** Caddy issues a real Let's Encrypt cert automatically — no DNS setup.
- **Backup:** `ttionya/vaultwarden-backup` sidecar → encrypted daily archive to Google Drive.

## Files

| File | Purpose |
|------|---------|
| `docker-compose.yml` | vault + Caddy + backup sidecar (backup gated behind a compose profile) |
| `Caddyfile` | reverse proxy + automatic HTTPS + WebSocket |
| `bring-up.sh` | runs on the box: installs Docker, opens 80/443, `docker compose up` |
| `../.github/workflows/deploy-vaultwarden.yml` | manual (workflow_dispatch) deploy over SSH |

Nothing sensitive is committed — `.env` and `rclone.conf` are generated by the
workflow from secrets and land only on the server (chmod 600).

## How to deploy

### 1. Add two GitHub secrets (repo → Settings → Secrets and variables → Actions)

Reuses the existing `ORACLE_HOST`, `ORACLE_USER`, `ORACLE_SSH_KEY_B64`. For the
backup add:

- **`VW_BACKUP_ZIP_PASSWORD`** — password for the encrypted backup archive.
  Generate one and store it in your own password manager (you need it to restore):
  ```bash
  openssl rand -base64 32
  ```
- **`RCLONE_CONF_B64`** — base64 of an rclone config with a Google Drive remote.
  Create it once on your laptop (has a browser), then base64 it:
  ```bash
  rclone config          # add a remote named e.g. "gdrive", type "drive"
  base64 -w0 ~/.config/rclone/rclone.conf     # macOS: base64 -i ...
  ```
  Paste the single-line output as the secret value. (The remote's name is parsed
  automatically from the file — you don't need to match it anywhere.)

> Skipping backup for now? Set the **enable_backup** input to `false` when you run
> the workflow and omit these two secrets.

### 2. Run the workflow

Actions → **Deploy Vaultwarden to Oracle** → **Run workflow**.
- First run: leave **signups_allowed = true** so you can create your account.
- After you've registered at the URL, run it again with **signups_allowed = false**
  to lock the server down.

### 3. If the URL isn't reachable

The host firewall is opened by `bring-up.sh`, but the **OCI VCN Security List**
must also allow inbound **TCP 80 and 443** (`0.0.0.0/0`). Add those ingress rules
in the OCI console if the health check fails.

## Connect the Bitwarden apps

On the login screen choose **Self-hosted**, set the server URL to your
`https://vault.…nip.io`, then log in. Works for the browser extension, mobile,
and desktop apps.

## Restore a backup

```bash
# on the box, in ~/vaultwarden
sudo docker compose down
# download the archive from Drive with your rclone remote, then:
unzip -P '<VW_BACKUP_ZIP_PASSWORD>' <archive>.zip -d ./restored
rm -rf data/vw-data && mv ./restored data/vw-data
sudo docker compose --profile backup up -d
```
